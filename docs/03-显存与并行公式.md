# 03 · 显存与并行：4 卡跑起来的全部数学

## 三个数字先记牢

| 项 | 值 |
|---|---|
| 专家层（48×2.52B） | 120.8B 参数 = **241.6 GiB bf16** |
| PLE 表 | 51.2B 参数 = **95.4 GiB bf16**（LoRA 不训它） |
| 稠密层+嵌入 | ~5B 参数 ≈ 10 GiB |

## 切分公式

**专家必须 4 刀。** 官方 8 卡配方 TP2/EP4/PP2 的显存效率来自 EP4（专家 4 份）；4 卡等价物：

```
TP4 / EP1 / ETP4    ← expert_tensor_parallel_size 必须等于 TP
```

**ETP=1 而只设 TP4/EP2 时专家只被 EP 切 2 刀 = 120G/卡 → 实例化 TEColumnParallelGroupedLinear 时 OOM。**
这个错误没有任何提示指向 ETP，是本日最难定位的一坑。

## PLE 的归宿

`PLE_CPU_OFFLOAD=1`（mcore-bridge 机制）：
- 表驻留主机内存（940G 内存机器无压力），查表时只传命中行（几 MB/步）；
- 官方实测仅 4% 减速；LoRA 本来就不更新它，零精度损失。

## 实测数据（4×A800-80G, bf16 LoRA r8, seq4096）

| 配置 | 显存/卡 | 步时 | 备注 |
|---|---|---|---|
| TP4/ETP4/micro1 | 63.4 GiB | 46.7s | 首版 |
| TP4/ETP4/micro2 | 73.4 GiB | **24-28s** | 等效 batch 不变（global 8 = 2×4），提速 42% ✅ |
| GPU 利用率 | 92–97% | | NVLink 的 SXM 版卡才有的待遇 |

对照官方 8 卡基准：TP2/EP4/PP2 + PLE offload + seq4096 = 63.6 GiB/卡——4 卡配方与其同构。

## 官方 8 卡 → 4 卡的参数映射表

| 官方（8卡） | 本仓（4卡） |
|---|---|
| tensor_model_parallel_size 2 | **4** |
| expert_model_parallel_size 4 | **1** |
| expert_tensor_parallel_size 1 | **4** |
| pipeline_model_parallel_size 2 | 1 |
| decoder_first_pipeline_num_layers 12 | 删（无 PP） |
| PLE_CPU_OFFLOAD=1 | 保持 |
| 其余（recompute/padding_free/seq/batch/lr） | 保持 |
